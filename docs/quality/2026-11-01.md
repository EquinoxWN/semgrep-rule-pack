# Quality check against the 10 rules (2026-11-01)

Applied while building M1 (recorded 2026-11-10) on Windows 11 (Intel Core i7-13700H) with Python
3.14.5 in the repo's `.venv` and Semgrep 1.184.0. Mutations were applied one at a time by a script
that restores each file in a `finally` block; the fast suite (`pytest -m "not semgrep"`) judged
harness mutants and `srp test` with the real Semgrep judged rule mutants.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | The only external call is the Semgrep subprocess (`runner.py`): overall timeout (default 600 s, `--timeout`), exit codes other than 0 and 1 raise, unreadable JSON raises, output over 256 MB raises, a missing binary raises. Semgrep reports a rule parse error in its JSON while exiting 0; `parse_output` raises on any reported error (found while building: a Go pattern error passed silently). No retries: a local scan is deterministic, so a retry would only repeat the failure. Each failure path has a test with a fake Semgrep. |
| 2 | Writes safe to retry | pass | `srp test --json` and `srp scan --json` write a sibling `.tmp` file and `os.replace` it (`write_json_atomic`); a test re-writes and checks no temp file remains. Semgrep's settings file lives in a per-run temporary home that is removed afterwards. |
| 3 | No race conditions | fixed | Semgrep rewrites its settings file on every start; on Windows the rename raced with its own reads and failed with `PermissionError`. The runner now writes a read-only settings file in a fresh temporary home per scan, so concurrent scans share nothing. |
| 4 | Don't trust the clock | pass | Scan durations use `time.monotonic`; stored report times are UTC (`datetime.now(UTC)`, tested to end in `+00:00`). |
| 5 | Read before changing | pass | No environment variables are read by the harness; the variables it sets for the Semgrep child (`HOME`, `USERPROFILE`, `XDG_*`, `SEMGREP_SETTINGS_FILE`, `SEMGREP_LOG_FILE`, `SEMGREP_ENABLE_VERSION_CHECK=0`, `SEMGREP_SEND_METRICS=off`) are listed in the README. Every README link exists (audit). |
| 6 | Never break compatibility | pass | Fixtures use the standard `semgrep --test` annotations, and `semgrep --test rules` passes as well as `srp test` (tested). Rule ids are stable and prefixed by language. |
| 7 | One source of truth | pass | Rule metadata lives only in the YAML; the harness reads it. Semgrep is pinned once (`semgrep==1.184.0` in `pyproject.toml`), Python >=3.11 in `pyproject.toml`, CI and README. |
| 8 | Small changes, no secrets, validate input | pass | Rule files are parsed with `yaml.safe_load`, capped at 256 KB; fixtures capped at 1 MB; schema, id prefix, metadata, `$<digit>` in messages (Semgrep substitutes it; found while building) and fixture coverage are validated. CLI rejects non-positive timeouts, empty commands and missing scan paths (exit 2). The subprocess gets an argument list, never a shell. Fixtures contain deliberately vulnerable code but no secrets and are never run. |
| 9 | Tests that can actually fail | pass | Empty, invalid and failure paths are covered (malformed annotations, 18 schema violations, bad YAML, missing fixtures, duplicate ids, Semgrep crash, timeout, garbage output, reported errors). 13/13 mutants killed. |
| 10 | Re-verify | pass | `.tmp/check.sh` run twice, both `CHECK PASS` (see below). |

## Defects found while building (Analyze, Improve)

| Defect | Found by | Fix |
|---|---|---|
| `go-tainted-sql` reported `db.Query("... $1", v)`: the `($CTX, $QUERY)` sink shape also matched database/sql calls, so the bound parameter `v` became a sink | generated taint matrix (`test_taint_fires_exactly_when...[go]`): 3 unexpected findings | context-first shape limited to `*Context` methods and to a context-like first argument; regression `ok:` case added |
| `go-sql-string-building` missed pgx's `pool.QueryRow(ctx, fmt.Sprintf(...))` | read-only scan of `zero-downtime-resharding` (0 findings where the grep showed two) | context-first shape allowed for `Query`, `QueryRow`, `Exec` when the first argument is context-like; fixture cases for pgx added; the scan now reports 6 sites there |
| `java-weak-crypto` flagged `AES/GCM/NoPadding` (regex `aes(/.*)?`) | `semgrep --test` | only bare `"AES"` (ECB by default) and explicit `/ECB/` match |
| Concatenation `"..." + x + "'"` missed in Python, Go, Java | `semgrep --test` | added the three-operand form |
| Messages containing `$1` were garbled by Semgrep | manual scan output | messages rewritten; `srp validate` now rejects `$<digit>` |
