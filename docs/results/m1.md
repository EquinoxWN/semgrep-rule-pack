## Scan of portfolio repositories (read-only)

`srp scan` over the source folders of eight portfolio repositories that a text search had flagged
(zero-downtime-resharding, dbt-analytics-warehouse, idempotent-backfill-kit,
realtime-olap-benchmark, otel-polyglot-tracing, chaos-gamedays, flash-sale-engine,
lora-finetune-pipeline): **24 findings in 11 files, 19.0 s**.

| Rule | Findings | Triage |
|---|---|---|
| `python-sql-string-building` | 17 | Table names, quoted identifiers (`quote(...)`), placeholder lists and an integer pragma spliced into DuckDB, SQLite and MySQL statements. All values come from code or config, none from request input. Not exploitable as written; the pattern is the one that becomes SQL injection once an identifier comes from a user. |
| `go-sql-string-building` | 6 | pgx `QueryRow` / `Exec` with `fmt.Sprintf` or `+` on a table or publication name derived from a tenant id inside the resharding tool. Same assessment. |
| `java-weak-crypto` | 1 | `MessageDigest.getInstance("SHA-1")` to compute a Redis script SHA for `EVALSHA`: SHA-1 is required by the Redis protocol and is not a security control. A `nosemgrep` comment with that reason is the right fix there. |
| taint rules (6) | 0 | No request input reaches SQL text or a shell in these repositories. |
| deserialization rules | 0 | `chaos-gamedays` loads YAML with a `SafeLoader` subclass and `lora-finetune-pipeline` calls `torch.load(..., weights_only=True)`: both are the safe patterns the rules allow. |

The scan found a false negative in the pack itself: before the fix, `go-sql-string-building`
missed pgx's context-first `QueryRow(ctx, fmt.Sprintf(...))` (0 findings in
zero-downtime-resharding where a text search showed two). See the quality report.

## Dependency audit

`pip-audit --skip-editable`: no known vulnerabilities in the harness's dependencies. Five advisories
are ignored by id: four in `mcp` 1.29.0 and one in `opentelemetry-api` 1.37.0. Semgrep 1.184.0, the
latest release on 2026-11-10, pins both exactly (`mcp==1.29.0`, `opentelemetry-api~=1.37.0`), so
they cannot be upgraded without breaking Semgrep. The harness never starts Semgrep's MCP server and
does not configure OpenTelemetry export. The ignores are listed in the `Makefile` and go away when
Semgrep lifts the pins.

## Lean Six Sigma summary

- **Define:** CTQs in [RFC 0001](../rfc/0001-design.md).
- **Measure:** the tables above (fixture scores, matrix, portfolio scan).
- **Analyze:** five defects found while building (Go context sink, pgx miss, Java AES regex, three-
  operand concatenation, `$1` in messages), root causes in the quality report.
- **Improve:** each fixed with a regression fixture case; validator now rejects `$<digit>`.
- **Control:** CI runs lint, tests, `srp validate`, `srp test`, `semgrep --test` and `pip-audit`
  on every push and prints the rule score as a `::notice`.
